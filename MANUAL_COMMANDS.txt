--- A1. Clone Repository (First Download from GitHub) ---
:: Open CMD / PowerShell in the folder where you want the project, e.g.:
cd C:\Users\Fouad\OneDrive\Desktop

:: Option 1 - Clone via HTTPS (no SSH key needed):
git clone https://github.com/Fo2shh/alf_hana.git shark2

:: Option 2 - Clone via SSH (requires SSH key configured):
git clone git@github.com:Fo2shh/alf_hana.git shark2

:: Then enter the project folder:
cd shark2

--- A2. Push Local Existing Project to NEW GitHub Repository ---
:: Run these INSIDE the project folder (C:\Users\Fouad\OneDrive\Desktop\shark2):
git init
git add .
git commit -m "Initial commit - Alfhana Kitchen Django project"
git branch -M main
git remote add origin https://github.com/Fo2shh/alf_hana.git

:: If you already have a remote and want to update it:
git remote set-url origin https://github.com/Fo2shh/alf_hana.git
git push -u origin main

--- A3. Pull Latest Updates from GitHub ---
:: Get latest changes that others pushed:
git pull origin main

:: Or simpler (if tracking is already set up):
git pull

--- A4. Daily Git Workflow (Your changes -> GitHub) ---
:: 1. Check what files you changed:
git status

:: 2. Add ALL changed files:
git add .

:: 3. Or add SPECIFIC files only:
git add core/views.py
git add requirements.txt
git add startfresh.bat start.bat

:: 4. Commit with a descriptive message (Arabic OK in messages):
git commit -m "Fix: resolve Django corrupted installation in venv"
git commit -m "Feature: add WhatsApp navigation buttons for drivers"
git commit -m "Update: refactor start.bat and startfresh.bat robustness"

:: 5. Push to GitHub:
git push

--- A5. Branch Commands ---
:: List all branches:
git branch

:: Create NEW branch and switch to it:
git checkout -b feature/map-improvements

:: Switch to existing branch:
git checkout main
git checkout feature/map-improvements

:: Merge a branch INTO current branch:
git checkout main
git merge feature/map-improvements

:: Delete a local branch after merging:
git branch -d feature/map-improvements

--- A6. Useful Git Utilities ---
:: View commit history (press q to exit):
git log --oneline --graph --decorate -20

:: See exact changes made to a file:
git diff core/views.py

:: Undo local uncommitted changes to a file:
git checkout -- core/views.py

:: Undo last commit but KEEP the changes in files:
git reset --soft HEAD~1

:: Undo last commit AND DISCARD the changes (CAUTION!):
git reset --hard HEAD~1

:: See remote repository URL:
git remote -v

[D] DJANGO MANAGEMENT COMMANDS
================================================================================
All commands below assume you are in: C:\Users\Fouad\OneDrive\Desktop\shark2
and use the pattern: venv\Scripts\python.exe manage.py <command>

--- D1. Database & Migrations ---
:: Create migration files after you change models.py:
venv\Scripts\python.exe manage.py makemigrations

:: Show what migrations exist and which are applied:
venv\Scripts\python.exe manage.py showmigrations

:: Apply all pending migrations:
venv\Scripts\python.exe manage.py migrate

:: Apply migration to a specific app only:
venv\Scripts\python.exe manage.py migrate core
venv\Scripts\python.exe manage.py migrate orders

:: Fake apply a migration (if you manually applied it already - advanced):
venv\Scripts\python.exe manage.py migrate --fake core 0001_initial

:: Rollback (undo) migrations to a specific point:
venv\Scripts\python.exe manage.py migrate core zero        :: Undo ALL core migrations
venv\Scripts\python.exe manage.py migrate core 0003        :: Undo back to migration 0003

:: Print the raw SQL that a migration would run:
venv\Scripts\python.exe manage.py sqlmigrate core 0001_initial

--- D2. Static Files ---
:: Collect all static files from apps into STATIC_ROOT (staticfiles/):
venv\Scripts\python.exe manage.py collectstatic --noinput

:: Clear old static files before collecting:
venv\Scripts\python.exe manage.py collectstatic --clear --noinput

--- D3. Users & Superuser ---
:: Create a NEW superuser (interactive - asks for username/password):
venv\Scripts\python.exe manage.py createsuperuser

:: Create a user with NON-INTERACTIVE one-liner (script):
venv\Scripts\python.exe -c "import os,django; os.environ['DJANGO_SETTINGS_MODULE']='alfhana_kitchen.settings'; django.setup(); from core.models import User; u,_=User.objects.get_or_create(username='myuser',defaults={'email':'a@b.com','role':'admin','phone':'01000000000'}); u.set_password('mypassword123'); u.is_superuser=True; u.is_staff=True; u.save(); print('User saved')"

:: Or simply run the existing script (creates 3 default users):
venv\Scripts\python.exe create_admin.py

:: Change password for an EXISTING user:
venv\Scripts\python.exe manage.py changepassword admin

--- D4. Server & Shell ---
:: Run development server on default port 8000:
venv\Scripts\python.exe manage.py runserver

:: Run server on a specific PORT:
venv\Scripts\python.exe manage.py runserver 8080
venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000   :: Allow access from LAN

:: Open Django Python shell (interactive):
venv\Scripts\python.exe manage.py shell

:: Inside shell, you can test queries:
::   from core.models import Customer, User
::   User.objects.all()
::   Customer.objects.count()
:: exit() to leave

:: Check for Django project problems:
venv\Scripts\python.exe manage.py check

--- D5. Testing & Checking ---
:: Run all tests:
venv\Scripts\python.exe manage.py test

:: Run tests for specific app only:
venv\Scripts\python.exe manage.py test core
venv\Scripts\python.exe manage.py test orders

:: Run tests with more detail (verbosity 2):
venv\Scripts\python.exe manage.py test -v 2

:: Validate the whole Django project setup:
venv\Scripts\python.exe manage.py check --deploy

[E] VIRTUAL ENVIRONMENT (venv) COMMANDS
================================================================================

--- E1. Create & Delete ---
:: Create venv in current folder (called "venv"):
python -m venv venv

:: Create with specific Python version (if you have multiple):
py -3.11 -m venv venv
py -3.10 -m venv venv

:: DELETE venv completely (clean slate):
rmdir /s /q venv

--- E2. Activate & Deactivate ---
:: NOTE: Activation is OPTIONAL. Our project uses the DIRECT PATH pattern
:: "venv\Scripts\python.exe" which works WITHOUT activation and is more reliable.
:: But if you want to activate:

:: Activate in CMD (old command prompt):
venv\Scripts\activate.bat

:: Activate in PowerShell:
venv\Scripts\Activate.ps1
:: (If you get ExecutionPolicy error, run first: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser)

:: After activation, you can just type "python" instead of full path:
::   python manage.py runserver

:: Deactivate (go back to system Python):
deactivate

--- E3. pip Package Manager ---
:: IMPORTANT: Always use this pattern for reliability:
::   venv\Scripts\python.exe -m pip <command>
:: NOT just "pip" which may use system pip by mistake.

:: Install package:
venv\Scripts\python.exe -m pip install django
venv\Scripts\python.exe -m pip install django==5.1.7
venv\Scripts\python.exe -m pip install "django>=5.0,<6.0"

:: Install from requirements.txt:
venv\Scripts\python.exe -m pip install -r requirements.txt

:: Install and force-reinstall clean copy:
venv\Scripts\python.exe -m pip install --no-cache-dir --force-reinstall -r requirements.txt

:: Uninstall package:
venv\Scripts\python.exe -m pip uninstall -y django

:: Upgrade ONE package:
venv\Scripts\python.exe -m pip install --upgrade django

:: Upgrade pip itself:
venv\Scripts\python.exe -m pip install --upgrade pip

:: List installed packages:
venv\Scripts\python.exe -m pip list

:: See details for a package:
venv\Scripts\python.exe -m pip show django

:: Freeze (export) current packages INTO requirements.txt:
venv\Scripts\python.exe -m pip freeze > requirements.txt

:: Search packages (online):
venv\Scripts\python.exe -m pip search leaflet

--- F4. Common Errors and Command Fixes ---

:: ERROR: "ModuleNotFoundError: No module named 'django'"
:: FIX  : Packages not installed. Run:
venv\Scripts\python.exe -m pip install -r requirements.txt

:: ERROR: "No module named 'django.utils'" or similar partial import
:: FIX  : Corrupted installation. Run:
venv\Scripts\python.exe -m pip install --no-cache-dir --force-reinstall -r requirements.txt

:: ERROR: "Virtual Environment not found" when running start.bat
:: FIX  : Run startfresh.bat first, or manually create venv:
python -m venv venv

:: ERROR: "You have unapplied migrations" warning on server
:: FIX  : Run migrations:
venv\Scripts\python.exe manage.py migrate

:: ERROR: "OperationalError: no such table: core_order"
:: FIX  : You deleted DB but didn't migrate. Run:
venv\Scripts\python.exe manage.py makemigrations
venv\Scripts\python.exe manage.py migrate

:: ERROR: Static files not showing (404)
:: FIX  : Collect static and make sure DEBUG=True in settings.py:
venv\Scripts\python.exe manage.py collectstatic --noinput

:: ERROR: "Port 8000 is already in use"
:: FIX 1: Close the other server window running on 8000
:: FIX 2: Use different port:
venv\Scripts\python.exe manage.py runserver 8080

:: ERROR: In PowerShell: "Scripts not signed" or "ExecutionPolicy"
:: FIX  (PowerShell only - run once):
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
:: Then press Y to confirm.
